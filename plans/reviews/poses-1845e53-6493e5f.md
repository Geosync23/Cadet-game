## 0.27.44: shallower deep seats (behaviour, reviewed in depth)
**What changed:**
- The `armchair`, `sofa` and `beanbag` kits are shallower. The returned `w`/`d` are unchanged, so footprints, blocking and taps stay put.
- Their 36 sit places get `cush: .2`, new `xy` spots, and a numeric `face` on 8 turned seats.
- `seatCushion` looks up `cush` by position in `SEAT_RC.cushK`. That's a flat list of numbers, built with the mesh list once per deck load and emptied by `deckUnloaded` (via `gen`/`list`), so the 0.27.43 heap fix stands.

**Checked:**
- **The tag lookup matches real sitters.** Settled crew take `x = spot.x` and `z = spot.z` exactly (the two settle paths in the crowd code), and `placeSpot` returns the same `spot` object. So the < .05 position match finds the tag, and untagged seats keep .3.
- **Numeric faces.** `placeSpot` already turns a number into degrees (0 south, 90 east), as the card-table stools use. The Deck 3 crowd `spots()` code that reads `FACE[p.face]` only reads mess seats and the servery, not lounge places.
- **Spot moves fit the kits.** Example: 2-armchair-9 moved .39 m to 3.04. The chair is at room x 3.15, and the sitter sits .105 behind its centre, as the handover says. 2-armchair-10, which faces west, fits the same way.
- **Walk tiles** (`poses-1845e53-walk-probe.py`, every place on Decks 2-6, 0.27.43 against 0.27.44): no changes except **6-watch-1: 12,7 → 13,8** and **6-watch-2: 12,10 → 13,9**. The new spots (x 13.01) are in tile 13, and the open tile next to them is chosen by `placeSpot`'s usual rule (same room, edge open, reachable from the lift). That's fine: crew now step in from the tile the spot is in.
- **Crew plans** (`poses-1845e53-plans-probe.py`, days 1, 2, 3, 5 and 8): 26 steps differ, all **Deck 3 lounge seat picks** (which lounge seat someone takes, and with it read/talk/drink). One knock-on: soto-marta's day 1 evening lounge stay ends at 20:35, not 21:50, because she picks a drink seat instead of a talk seat. This is expected when seat spots move, since seat choice reads spots. deck architect 3's day_check day 1 on 0.27.45, which includes 0.27.44, was OK.
- **Cost.** The cushK scan is at most 36 entries, and only runs when a sitter's cached ray is out of date. Building cushK calls `placeSpot` for each tagged place, once per deck load; it's cached in `SPOT_OF` and usually already filled by the scheduler.

**INFO 1:** the plan reshuffle above is a real schedule change on Deck 3 (seat picks only, no one stuck, no new places). It's just so the build master isn't surprised by day_check or plan diffs.

**INFO 2:** perf_check. Deck architect 3 reports draw calls and heap identical to 0.27.43. The game-time flag at Sunday dinner looks like machine noise (±0.5 ms is normal), and the rerun is pending. The code can't plausibly add per-frame time, because the ray is cached per person. Please get the rerun result from deck architect 3 before releasing; I don't need it for this verdict.
