### MEDIUM 1 (0.27.40): +40 MB of JS heap
40 MB is a lot on a phone; the budget gives memory a lot of weight.
- **Likely cause:** the raycast cache keeps a deck's furniture alive after you leave it. `SEAT_RC.root` and `list` are set to the deck's `deckRoot` and its 600-800 meshes, and every seated handle's `o.cush.root` points at that `deckRoot`. They're only replaced the next time someone sits on another deck.
- **Fix:**
  - key the cache on `deckDef.num` (or a deck-load counter) instead of holding `deckRoot`;
  - empty `SEAT_RC.list`/`root` when a deck unloads;
  - then find what else holds it, since clearing those two wasn't enough in my probe.
- **Test:** perf_check's round-trip heap should be back to 150 MB.

### LOW 1 (0.27.40): dinner game code about +0.6 ms a frame
The rise is about +40% in the busiest seated scene; a mid phone is about 4-5× slower, so roughly +2.5 ms there. The rays are cached, so this is the per-frame sit block for 75 people. Possible causes:
- `seatCushion`'s cache test runs each frame for each seated, posed person;
- the extra `asin`/`legIK` path.

Worth a profile. A small fix would be to cache `cu`/`kh`/`th` on `o.cush` with the value.
